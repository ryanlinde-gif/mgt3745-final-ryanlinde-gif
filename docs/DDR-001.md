# DDR-001: Claude on the Sourcing Audit

## Task

`docs/SOURCING-AUDIT.md` for Audit 1: the inventory, the dated evidence, the
prose around the scores, the exit-plan table, and `evals/supply-chain.test.js`.

**Not delegated.** The four weights and the sentence justifying each. The
Prediction Stake and its resolution type. All forty-four scores. Every ring,
including the two where the ring disagrees with the weighted total. The decision
to pin `wrangler` rather than remove something.

## Tool and Model

Claude Opus 5, via Claude Code, 2026-11-11.

## Economic Rationale

| | Hours |
|---|---|
| By hand: twelve rows of lookups, four pages of limits, scoring, prose | 5.0 |
| The delegation itself | 0.7 |
| Review, correcting the eval, checking each number | 1.3 |
| **Net** | **-3.0** |

Worth it. The saving is in assembly, not judgment: running `npm view` twelve
times and reading three Cloudflare pages is exactly the work a tool with shell
access does faster. Choosing the weights took the same time either way.

## Trust Boundary

This repository, its `package.json`, and the public npm and Cloudflare pages
crossed to Anthropic under the Claude Code terms. **No credential and no user
data.** The repository holds no athlete data yet; the exit test ran against my
own HW4 database and its output was git-ignored before the command was run.

**Reverse crossing: nothing.** No dependency was added by the tool. The one
package change, pinning `wrangler`, removed a range rather than adding anything.

## Retries and Changes

**One correction, and it is the useful part.** The first version of the
credential check in `evals/supply-chain.test.js` failed against
`worker/wrangler.toml`, matching the comments that correctly explain how to set
the secret with `wrangler secret put`. The test was wrong, not the repository.
It now strips comments and matches only a credential-shaped name assigned an
actual value. Recorded in the audit's Changes section as well as here, because a
check that cries wolf gets disabled, and a disabled check is worse than none.

## Verification Performed

Nothing in the audit was accepted on the tool's word:

- **The package count** came from `npm ls --all --parseable | tail -n +2 | wc -l`, run here: **35**. This is what resolved the Prediction Stake against me.
- **Versions, maintainers, licences** from `npm view` for wrangler, esbuild and workerd, all dated 2026-11-11.
- **The postinstall finding** came from reading every `package.json` in `node_modules` for install hooks, and matches the `allow-scripts` warning npm printed during install.
- **Service limits** fetched from `developers.cloudflare.com` and quoted with the date read, rather than recalled.
- **The exit test** was run for real: `npx wrangler d1 export mgt3745-entries --remote`, 1,096 bytes with the schema.
- **`npm test` run after every change.** 4 of 4 pass.

**What I could not verify.** Whether the two `postinstall` scripts do only what
they claim. Reading `node install.js` in `workerd` and `esbuild` would take
longer than this audit had, and the audit says Assess rather than Adopt for
exactly that reason.

## Outcome

The audit shipped, the Prediction Stake resolved against me, `wrangler` is
pinned, and four checks now fail if ADR-001's commitments stop being true.
