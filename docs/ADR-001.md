# ADR-001: Hand-build on Cloudflare Workers and D1, with no runtime dependencies

Status: accepted
Date: 2026-11-11

## Context

Recruiting Reality Check exists because of one gap in my own business: I can get
high school athletes to respond and show interest in recruiting help, and I
cannot reliably get from that interest to a conversation with a parent and a
paying client. `PROJECT.md` carries the full framing; `USERS.md` carries the job
statements from the interviews behind it.

Two forces shape the architecture rather than the product:

**The users are minors and their parents.** Anything this system stores about an
athlete is a record of a teenager's recruiting situation. That is not regulated
data, but it is the kind of thing a family would not want loose.

**I have to be able to audit it.** The HW3 Gate in `ARCHITECTURE.md` found that
the decision between hand-building and delegating turned on exactly one thing,
whether I could read the code well enough to check it. That finding is the
reason this project is structured the way it is.

## The Gate

Carried forward from `context/ARCHITECTURE.md`, where the full scoring and the
sensitivity tests live. Three doors, each scored at its most favourable honest
reading, including Buy as a free spreadsheet rather than a paid CRM.

**Build** won on 100, **Buy** 91, **Delegate** 84.

The margin was 9 points out of 120, close enough that the HW3 Gate tested
whether the result survived disagreement. It does: dropping the weight I was
least sure of, inspectability, from 5 to 3 narrows the margin to 5 and does not
change the order.

**What the Gate actually turned on.** Delegate scores 1 on inspectability
because, at the time of scoring, I could not read JavaScript well enough to
audit what a builder handed me. Raise that score to 5 and Delegate wins outright
at 104, with nothing else in the table changing. The decision rests on my own
literacy and on nothing else, which is why that is the reversal trigger below
rather than a date.

## Options considered

| Option | For | Against |
|---|---|---|
| **Build**: hand-written HTML, CSS and JavaScript on a Cloudflare Worker with D1 | I can read every line and therefore audit it. No runtime dependencies to trust. Free tier covers the whole project. The stack I have already deployed four times | Slowest to a first working version. Every feature is mine to write |
| **Buy**: an existing CRM or a spreadsheet | Fastest to something usable. Someone else maintains it | A spreadsheet cannot ask the disappointment question or run an eval. A real CRM is priced per seat and the data would live with a vendor I have not vetted |
| **Delegate**: generate the application from the spec with an AI builder | Fastest to a plausible build. HW6 showed a builder produce a working feature in minutes | HW6 also showed one ship 18 dependencies and a hosted database nobody asked for, and report "the page is complete and meets every acceptance criterion" while rendering blank. Scores 1 on inspectability for as long as I cannot check that claim myself |

## Decision

**Build.** One Cloudflare Worker serves the API. D1 holds the data. The page is
hand-written HTML, CSS and JavaScript with **no runtime dependencies and no
build step**. Tests run on Node's built-in `node:test` rather than a test
framework.

Delegation is still used, and used heavily, but as a **drafting tool under
review** rather than as the builder of record. Every delegated piece gets a DDR
naming what was delegated, what was verified, and how.

## Consequences

**What gets harder.** Every feature is mine to write, and the first working
version arrives later than it would from a builder. There is no component
library, no framework, and no one to ask when something does not work.

**What gets easier, and is the point.** There is no dependency I cannot read,
no vendor holding athlete data, and no build step between the source and what
ships. The sourcing audit in `docs/SOURCING-AUDIT.md` exists to keep that true
rather than merely assert it.

**Reversal trigger.** Not a date. **The day I can read generated JavaScript well
enough to audit it line by line**, Delegate scores 5 on inspectability, wins the
Gate at 104, and this ADR should be superseded. The Gate's own sensitivity test
says nothing else has to change for that to happen.

**Second trigger.** If the project ever needs to hold data for a real athlete
rather than synthetic records, authentication has to exist first, and that is a
decision this ADR does not make.
